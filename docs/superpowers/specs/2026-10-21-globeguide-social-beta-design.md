# GlobeGuide 社交内测版设计

日期：2026-10-21
状态：待用户审阅

## 目标与边界

在现有 Travel Notes、邮箱账号、Cloudflare Pages Worker + D1 的基础上，增加一个可测试的文字社交闭环：用户可以发现作者、关注、互动、私信和建立群聊；用户可以管理自己的内容和关系；管理员可以处理举报和违规内容。

本期内容为纯文字。帖子和消息暂不开放图片、视频、音频、文件、外链预览或任意 HTML。游客继续可以浏览公开帖子和用户资料；登录只在互动、发帖、私信和关系管理时要求。图片/视频上传另立一期，届时增加对象存储、压缩、内容审核、版权和带宽方案。

## 方案取舍

| 方案 | 好处 | 代价 | 决定 |
| --- | --- | --- | --- |
| 同源 Pages Worker + D1，消息用短轮询 | 复用现有 Cookie、Origin 校验和 Cloudflare 部署；开发、测试和内测运维简单 | 消息不是严格实时，客户端需要按游标刷新 | 本期采用 |
| D1 + Durable Objects WebSocket | 可提供实时消息、在线状态和群聊广播 | 引入连接生命周期、重连、状态同步和更多部署复杂度 | 后续升级 |
| 外部社交/聊天 SaaS | 功能上线快 | 账号、数据、审核和费用依赖第三方 | 不采用 |

## 用户、关系与隐私

新增用户资料字段或资料表保存公开昵称、简介、头像首字母、语言、旅行偏好和创建时间。邮箱、会话令牌和管理角色继续由现有认证表控制，不能从客户端提交的角色字段获得权限。

关注是单向关系。用户可以关注、取消关注、移除自己的粉丝；同一关系只能存在一条。被拉黑后，双方在公开列表、搜索、评论、点赞、关注推荐和私信中互相隐藏；拉黑会撤销双方关注，并阻止新的私信和群聊邀请。解除拉黑不会自动恢复关注。

账号设置提供隐私入口，包括查看自己的关系、查看已拉黑用户、取消关注和退出群聊。账号删除采用可恢复期软删除：公开资料隐藏，自己的帖子和评论标记为已删除，消息保留必要的会话完整性但显示为“已删除用户”。真正的个人数据清理作为后续合规任务，不在本期自动执行。

## 帖子互动

在帖子详情和帖子卡片提供点赞、收藏、分享、评论入口。点赞和收藏使用用户与帖子唯一约束，重复操作幂等；分享记录分享事件用于统计，并复制站内链接，不复制正文和第三方内容。

评论表包含帖子、作者、正文、父评论、状态、创建时间和软删除时间。回复最多两层；删除自己的评论显示占位文本并保留审核关联。评论、帖子和用户都支持举报，举报进入同一管理员队列并保留理由、状态、处理人和处理时间。

Feed 提供 `For you`、`Following`、`Saved` 三个视图：`For you` 按已发布内容的时间和互动信号排序，`Following` 只返回已关注作者，`Saved` 返回当前用户的收藏。首期不做复杂推荐模型，排序规则保持可解释。

## 私信与群聊

一对一会话由两个成员组成；群聊由创建者、普通成员和可选管理员组成。群主可以改名、邀请成员、移除成员、设置管理员和解散群聊；成员可以退出群聊并静音。被拉黑的双方不能创建新会话、发送消息或互相邀请入群。

消息只支持纯文字，长度限制为 2,000 字符。每条消息保存发送者、会话、正文、创建时间、删除时间和审核状态。用户可以删除自己的消息，界面显示“消息已删除”；不能修改他人消息。会话列表按最后一条消息排序，消息读取使用 `lastMessageId` 游标短轮询，避免重复拉取。

首期不显示在线状态，不承诺严格实时送达；前端在打开会话时刷新，发送成功后立即更新本地列表。后续需要实时体验时，将消息广播迁移到 Durable Objects WebSocket，D1 继续作为持久化来源。

## API 与数据迁移

新增 D1 migration `0003_social.sql`，表按职责拆分：

- `profiles`：公开资料和资料更新时间。
- `follows`：关注关系、创建时间、唯一约束。
- `blocks`：拉黑关系、创建时间、唯一约束。
- `post_comments`：评论、回复关系和软删除状态。
- `post_likes`：点赞唯一关系。
- `post_bookmarks`：收藏唯一关系。
- `post_shares`：分享事件。
- `conversations`、`conversation_members`：私信和群聊元数据、成员角色、静音和退出时间。
- `messages`：会话消息、发送者、正文和删除状态。
- `message_reads`：成员已读游标。
- `social_reports`：用户、评论、帖子和消息的统一举报记录；迁移脚本将现有 `post_reports` 转入同一目标模型，并保留兼容读取，避免出现两套管理员队列。

新增同源接口模块，所有写请求复用现有 Origin、会话和邮箱验证检查：

- `/api/profiles`：资料读取和本人资料修改。
- `/api/follows`、`/api/blocks`：建立、取消和列表操作。
- `/api/interactions`：点赞、收藏、分享和计数。
- `/api/comments`：评论、回复、删除和举报。
- `/api/conversations`、`/api/messages`：会话、群成员、消息、已读和删除。
- `/api/social-reports`：统一举报和管理员处理。

所有列表查询都应用拉黑过滤；未发布、删除或被隐藏的内容不会通过公开接口泄漏。接口对评论、点赞、关注、消息和群聊邀请设置按用户限流，避免刷量和骚扰。

## Web 页面与组件

- `/profiles/[id]/`：头像首字母、昵称、简介、关注状态、关注/粉丝数量、公开帖子和关系菜单。
- `/inbox/`：会话列表、群聊创建、会话设置和消息面板。
- `/stories/`：Feed 视图切换、互动按钮、评论入口和作者关注按钮。
- `/stories/post/`：完整互动栏、评论区、举报菜单和分享链接。
- 账号菜单：已关注、粉丝、已拉黑、通知偏好和账号删除入口。

按钮使用明确的图标和标签，所有危险操作（拉黑、删除、退出群聊）需要二次确认；互动失败显示可恢复的状态提示，不阻塞游客浏览。

## 内测系统账号

提供独立 seed 脚本创建已验证的测试账号：

- GlobeGuide Official
- Tokyo Explorer
- Silk Road Notes
- Weekend Atlas

脚本通过环境变量接收一次性密码或随机生成密码，只在执行结束时输出凭据；密码、会话令牌和测试邮箱不写入仓库。系统账号可以发布已审核的示例文字内容，用于测试关注、评论、收藏、转发和私信，不伪装成真实用户。

## 测试与验收

- 未登录用户可以浏览公开资料、Feed、帖子、评论和分享链接。
- 登录用户可以关注/取消关注、移除粉丝、拉黑/解除拉黑、点赞、收藏、评论、回复和删除自己的内容。
- 拉黑后双方不能在公开列表中互相看到，也不能发送私信或群聊邀请。
- 一对一会话和群聊可创建、邀请、移除、静音、退出，消息游标不会重复或跳过。
- 用户和管理员权限、软删除、举报状态、限流和同源校验有 API 测试覆盖。
- 线上 D1 migration、seed 和回滚说明写入 README；测试账号凭据不进入 GitHub。
- Web 类型检查、Worker 单元测试、API 集成测试、静态构建和桌面/手机主流程均通过后再发布。
