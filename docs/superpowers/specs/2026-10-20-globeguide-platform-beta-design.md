# GlobeGuide 平台内测扩展设计

日期：2026-10-20  
状态：实施中

## 目标与边界

GlobeGuide 保持匿名可浏览，在现有三城深度指南之外提供全球交互地图、完整的中国省级中心城市目录，以及围绕城市组织的创作者攻略和旅行日常。登录和注册只在用户要发布、互动或管理内容时出现；页眉角落保留独立的登录、注册入口。

首批城市覆盖大陆 31 个省级行政区中心城市，香港、澳门、台北另作城市入口；东京、巴黎、纽约继续保留深度指南。新增城市有可搜索的中英文名称、坐标、地区和简短原创介绍，但不虚构官方路线、票价、营业时间或完整攻略。首页只展示少量精选城市、地图入口、地区探索和内容预览，不堆放 37 张城市卡。

既有 `apps/api` 的 PostgreSQL/PostGIS 服务暂供本地地理开发；公开网站继续用 Next.js 静态导出部署 Cloudflare Pages。新增同源 Pages Worker 和 D1 承载账号、会话、帖子、互动和审核。后续如迁移到常驻 Nest API，必须按公开 API 契约迁移数据，不能把 D1 当作现有 Prisma 数据库直接复用。

## 方案取舍

| 方案 | 好处 | 代价 | 决定 |
| --- | --- | --- | --- |
| Pages 静态前端 + 同源 Worker/D1 | 利用现有 Cloudflare 部署、同源 Cookie、无需常驻服务器 | 社区帖子详情先由客户端读取，搜索引擎收录较弱 | 本期采用 |
| Nest API + 托管 PostgreSQL | 可复用现有 Prisma/PostGIS，适合后期复杂地理查询 | 需要新主机、数据库、跨域会话和持续运维 | 后期评估 |
| 外部 Auth/CMS SaaS | 快速获得管理后台 | 数据和用户体验依赖第三方，仍需邮件与内容治理配置 | 暂不采用 |

## 账号与邮件

游客可浏览城市、地图、官方来源和已发布内容。注册流程必须先申请邮箱验证码，再提交验证码、密码和公开显示名称；不能仅凭邮箱和密码创建账号。登录使用邮箱和密码；提供登出、会话查看、忘记密码及邮箱验证码重置密码。密码用 WebCrypto PBKDF2-SHA-256 加随机盐和明确的迭代参数存储；验证码只存带密钥的摘要，10 分钟过期、限制重试、单次消费。登录、发码和重置按 IP/邮箱限流，统一返回避免账号枚举。

会话为随机不透明令牌，D1 只保存令牌哈希；生产 Cookie 采用 HttpOnly、Secure、SameSite=Lax、Path=/ 且不设置 Domain。所有写请求只接收同源 JSON，并验证 Origin。作者只能修改自己的内容；管理员权限由数据库角色控制，不从客户端参数推断。

当前没有自有发件域名和事务邮件服务。开发/自动化测试使用只在本地启用的邮件收件箱接口；公网环境可部署认证 API 和登录页面，但申请验证码明确返回服务未启用，注册表单展示真实状态，不显示或泄漏验证码。配置经验证的邮件发件域名与服务密钥后，启用相同注册 API 的真实发信适配器。首个管理员通过部署者控制的独立引导步骤建立，凭据不入仓库。此测试模式不声称完成真实邮箱所有权验证。

既有收藏与行程仍是浏览器本地数据；登录不会暗中同步或抹除它们。账号同步是后续独立迁移。

## 地图与城市

使用 MapLibre GL JS 和可配置的 OpenFreeMap 矢量样式，在 `/map` 呈现全球地图。保留底图版权归属；地图服务失败时城市列表仍可用。桌面为地图与城市列表并排，手机提供地图/列表切换。搜索、地区筛选、城市选中、地图定位和列表焦点相互同步；地图 marker 与列表均可进入城市详情；提供恢复全球视角按钮，并支持键盘访问列表。地图默认不请求用户精确位置。

城市目录与深度指南分离。目录是全站地点 ID、名称、别名、行政地区、WGS84 坐标和简短描述的单一来源；深度指南只附着在已有的东京、巴黎、纽约。新增城市详情显示地点基础信息、地图、相关创作者内容，以及明确的“完整指南筹备中”状态。目录坐标和地名保留数据来源署名；中国境内地图服务与坐标系合规在进入大陆市场前单独审核。

## 创作者内容

登录用户可建立公开资料，发布两类内容：`guide`（攻略）和 `moment`（旅行日常）。第一期采用纯文本正文、标题（攻略必需）、语言、关联城市和可选到访月份；不允许任意 HTML、外部图片链接或复制别的平台正文。作者可保存草稿、提交审核、编辑、撤回和软删除；公开内容修改后重新进入审核。匿名用户只能读取已发布的列表和详情，按城市与类型筛选，能够看到作者、发布时间、内容类型和来源身份。

管理员有待审列表及通过、退回、下架操作；每次操作保留操作者、原因和时间。登录用户可以举报已发布内容，重复举报和提交频率受限。没有媒体扫描、EXIF 清理和授权核验前不开放作者图片上传；公开卡片可复用平台已有获授权城市照片，并明确不冒充作者拍摄。首批平台自写示例内容标识为“GlobeGuide 编辑示例”，不冒充真实博主；实际旅行者内容只有经用户投稿和审核后才标识为创作者内容。

API 以 `/api/*` 提供：`auth` 发码/注册/登录/登出/重置/会话；`posts` 公开列表与详情、作者草稿/提交/修改/删除；`reports` 举报；`moderation` 管理员审核。D1 表保存用户、挑战、会话、帖子、举报、审核记录及必要限流状态。未发布、驳回和删除的正文不得从公开详情或列表泄漏。帖子详情用静态 `/stories/post/?id=` 客户端拉取；若社区内容成为 SEO 获客主渠道，后续迁移为服务端渲染。

## 内容与版权

官方来源仅提供链接和我们自己写的事实摘要，并注明核对时间。第三方平台的原创攻略、日常正文和图片不得未经授权搬运；可以链接原文、引用可核实的公开事实并重新撰写，或邀请原作者直接在 GlobeGuide 投稿。新增城市的基础信息不写动态票价和时刻。内容卡清楚区分官方来源、平台编辑和旅行者投稿。

## 验收

- 不登录即可搜索、浏览 37 个目的地入口、地图和已发布帖子，首页首屏保持品牌与主要搜索，下一段内容在手机及桌面可见。
- 31 个大陆省级中心城市及港澳台独立入口在目录、搜索、地图和详情中一致；东京、巴黎、纽约的深度指南不退化。
- 地图可缩放、拖动、搜索、筛选、选择和进入详情；瓦片失败时列表可操作；桌面和手机布局无重叠及横向溢出。
- 本地测试完成发码、注册、密码登录、错误码/过期/限流、登出和重置；公网无发信配置时如实提示不可注册。
- 作者权限、审核状态和公开读取边界通过 API 与浏览器测试；草稿和待审内容不泄漏。
- CI 运行类型检查、单元测试、静态构建与桌面/手机浏览器主流程；Cloudflare 线上核对通过，仓库保持私有。
